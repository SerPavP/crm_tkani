# Правила: Backend (Django + DRF)

## Технологии и модули
- Django 5.x, DRF 3.15.x. Приложения: `clients/`, `deals/`, `fabrics/`, `warehouse/`, `finances/`, `core/`.
- Настройки и секреты — из переменных окружения. Не читать/не коммитить `.env`.

## Модели и данные
- Явно задавать `related_name`, индексы и ограничения (`UniqueConstraint`, `CheckConstraint`).
- Добавлять `__str__` и docstring к моделям/менеджерам.
- Денежные значения хранить как Decimal с указанной точностью. НДС и себестоимость — в явных полях/настройках.
- Миграции атомарные, осмысленные имена. Не править сгенерированные миграции вручную без необходимости.

## Сериализаторы и API (DRF)
- Использовать `ModelSerializer`. Валидировать бизнес-правила на уровне сериализаторов/сервисов.
- Фильтрация, сортировка, пагинация — стандартные механизмы DRF.
- Не раскрывать внутренние поля (себестоимость, приватные заметки) без явной необходимости.

## Вьюхи и маршрутизация
- Предпочитать class-based views и ViewSet'ы. Бизнес-логику выносить в сервис-слой `core/services.py` (или подмодули).
- Обрабатывать ошибки через явные исключения и корректные HTTP-коды.

## Транзакции и согласованность
- Запись нескольких связанных сущностей — в `transaction.atomic()`.
- Списания со склада и фиксация оплаты должны быть согласованными операциями.

## Производительность
- Избегать N+1: использовать `select_related`/`prefetch_related`.
- Для агрегатов (финансы) — `annotate`, индексы по полям фильтров/джойнов.
- Тяжёлую отчётность кэшировать и/или считать асинхронно (по необходимости).

## Безопасность
- `DEBUG=False` в проде, `ALLOWED_HOSTS` заданы. `SECRET_KEY` — только из окружения.
- CSRF включён, права доступа к API — через DRF Permissions/IsAuthenticated.
- Валидация входных данных строго до сохранения.

## Логирование и аудит
- Использовать стандартный логгер Django. Писать ключевые бизнес-события (создание/оплата сделок, списания склада).
- Логи не содержат персональные данные сверх необходимого.

## Тестирование
- Юнит-тесты на модели/сервисы, API-тесты на критические эндпоинты.
- Фикстуры/фабрики для данных. Тесты независимые, самодостаточные.

## Документация и поддержка
- Обновлять `project_overview.md`/`developer_guide.md` при изменении бизнес-логики.
- Публичные API документировать (drf-spectacular или др., по мере внедрения).
