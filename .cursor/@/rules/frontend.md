# Правила: Frontend (шаблоны и статика)

## Технологии и структура
- **Шаблоны**: каталоги в `templates/` по приложениям. Общие блоки — в `templates/_partials/`.
- **Статика**: хранить CSS/JS/изображения в `static/` (сборка в `staticfiles/`). Не класть сборки в Git.
- **Нейминг**: имена шаблонов по модулю, например `deals/list.html`, `fabrics/detail.html`.

## Шаблоны Django
- Использовать **extends** и **block**. Общий каркас: `base.html`.
- Контекст делать минимальным и явным; тяжёлую логику — в бэкенд/теги/фильтры.
- Не использовать `|safe`, кроме строго необходимых мест (с комментариями почему).
- Включать CSRF-токен во все формы: `{% csrf_token %}`.

## Формы и валидация
- Использовать Django Forms. Валидацию — в `clean()`/валидаторах, не в шаблонах.
- Обязательно отображать ошибки ввода рядом с полями.
- Для чисел/денег использовать маски ввода только как UX-слой, не как валидацию.

## JavaScript
- JS подключать снизу страницы или через `defer`.
- Избегать inline-скриптов. Скрипты — в `static/js/`, модульная структура, неймспейс `crm*`.
- События навешивать делегированно, не смешивать с HTML.
- Не обращаться напрямую к приватным API бэкенда; использовать документированные эндпоинты.

## Стили
- Методология: BEM или понятные утилитарные классы. Не использовать динамически генерируемые классы в шаблонах.
- Общие переменные/цвета — в одном месте. Поддерживать контраст и мобильную адаптивность.

## Доступность и UX
- Семантическая разметка, aria-атрибуты для интерактива.
- Фокус-стили не убирать. Управление с клавиатуры — обязательно.
- Формы: обязательные поля помечать, ошибок без всплывающих alert'ов.

## Производительность
- Минимизировать количество запросов: группировать ресурсы, использовать кеширование на уровне браузера/сервере.
- Изображения: webp/avif при возможности, задать размеры, `loading="lazy"`.

## Тестирование UI
- Критические пользовательские сценарии (создание сделки, добавление ткани, оплата) покрывать автотестами.
- Для e2e использовать Playwright. Сценарии держать атомарными и стабильными.
